Концепція

Endpoint — конкретна точка входу в API

Якщо API — це ресторан, то endpoint — конкретна страва в меню. Кожен endpoint — це URL + HTTP-метод, який виконує одну дію.

Один сервер — десятки endpoints: отримати список, створити запис, оновити, видалити — це все різні endpoints одного API.
HTTP методи
GETОтримати дані — нічого не змінює
POSTСтворити / надіслати дані
PUT/PATCHОновити існуючий запис
DELETEВидалити запис

Концепція

Webhook — "зворотній дзвінок" від сервера

API — це ти питаєш сервер. Webhook — це сервер сам тебе сповіщає, коли щось сталося. Webhook — це URL на твоєму сервері, який зовнішній сервіс викликає автоматично.

API: ти кожні 5 хв дзвониш у піцерію: "Ваша піца готова?"  |  Webhook: піцерія сама телефонує тобі коли готово.
Як налаштувати
Реєструєш свій URL у сервісі
Сервіс запам'ятовує його
При події — шле POST на твій URL
Твій сервер відповідає 200 OK

Ключова різниця

API vs Webhook

Не взаємовиключні — часто використовуються разом. Різниця в тому, хто ініціює комунікацію.

→ API (ти → сервер)

Ти ініціюєш запит
Отримуєш відповідь одразу
Polling — треба постійно питати
Підходить: пошук, отримання даних

← Webhook (сервер → ти)

Сервер ініціює при події
Real-time, без затримки
Ефективніше — нема зайвих запитів
Підходить: оплата, повідомлення, зміни
Реальний кейс — твій майбутній Крок 2.2

Gmail отримує лист → Webhook тригер сповіщає Make.com → Make.com через API надсилає повідомлення в Telegram.

📧 Gmail
— webhook →
⚙️ Make.com
— API →
✈️ Telegram

Це типова архітектура автоматизації — webhook як тригер, API як виконавець дії.
